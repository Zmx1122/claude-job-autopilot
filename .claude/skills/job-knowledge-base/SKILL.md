# Knowledge base

Goal: every file in `knowledge/library/` is a **unit file** — exactly one document (one certificate, one reference letter,
one CV variant), clearly named — and `knowledge/PROFILE.md` tells anyone (you, the user, a recruiter-minded reviewer)
what is there, what each document proves, and what is missing. Contents are git-ignored; never quote them outside this machine.

Layout:
```
knowledge/inbox/        ← the user drops anything here (or in the chat; copy it here)
knowledge/originals/    ← sources are moved here after processing (never edited, never uploaded)
knowledge/library/<kind>/<UnitFile>.pdf   ← generated unit files, the only files ever uploaded
knowledge/manifest.yaml ← machine index (generated by tools/kb_build.py)
knowledge/PROFILE.md    ← human-readable knowledge profile (written by you)
```

## A. Build or update (after the user adds files)
1. Put new files in `knowledge/inbox/` (copy files the user attached in chat; keep their names).
2. `python3 tools/kb_extract.py` → `data/kb/extract.json`: per page the text layer, OCR text (if tesseract is installed)
   and a PNG preview of **every** page.
3. **Dual review of every page — text and image, never one alone.** Read the page's text from the JSON *and* look at its
   preview PNG (or Read the PDF with `pages` when there is no preview). The image shows what text cannot: medals and
   placements, seals and stamps, signatures, logos, photos, handwritten notes, table layout. Example from real use: an AWS
   hackathon certificate whose text says "for successfully participating" carries a "1st" medal in the corner — it is a
   first-place certificate. When text, OCR and image disagree, trust what is visibly printed and record the difference
   in `facts` (e.g. `placement: 1st (medal)`, `body_wording: participating`) and in `visual_notes`.
   Decide where each document starts and ends. Typical bundles: a scan with Urkunde + Zeugnis + Notenspiegel;
   "Bewerbungsmaterialien.pdf" with several certificates; a 10-page "all documents" PDF. Blank pages and exact duplicates → `discard_pages`.
4. Write `data/kb/plan.json` (format in the docstring of `tools/kb_build.py`). For each document:
   - `kind` from the fixed list; `id` short and stable (`degree-msc-tud`, `ref-bosch-2023`, `cv-ai`).
   - `filename`: `<Kind>_<Issuer>_<Topic>_<YYYY[-MM]>.pdf`, ASCII, no spaces — e.g. `Degree_TU-Darmstadt_MSc-Urkunde_2021.pdf`,
     `WorkReference_Bosch_Arbeitszeugnis_2023.pdf`, `CV_AI-Engineer_EN_2026.pdf`.
   - `title`, `issuer`, `date`, `language`, `summary` (1–2 sentences: what the document is).
   - `facts`: concrete, checkable values (degree, field, grade, dates, level, score, role, employer).
   - `proves`: what it demonstrates to an employer (e.g. "Master's degree in mechanical engineering, grade 1.8",
     "German C1 officially certified", "led a 5-person team for 2 years — reference rates performance 'stets zu unserer vollsten Zufriedenheit'").
     Read Arbeitszeugnisse in their coded language and state the grade it implies.
   - `use_for`: job-title keywords where this document helps (CVs and topic certificates).
   - `visual_notes`: what only the image shows (medal, seal, signature present, scan quality, rotation), "" if nothing.
   - `sensitive: true` for ID cards, passports, residence permits, payslips, anything with tax or social-security numbers.
5. `python3 tools/kb_build.py data/kb/plan.json` — it refuses plans that leave pages unassigned or use a page twice.
6. Rewrite `knowledge/PROFILE.md` (template below) from `knowledge/manifest.yaml`.
7. Update `config/profile.yaml`: `candidate.cv_variants` → library CV paths; `documents:` → manifest ids;
   fill screening answers the documents settle (degree, grade, language levels).
8. Tell the user in a few lines: what was found, how it was split and named, the gaps.

## B. PROFILE.md template
```markdown
# Knowledge profile — <Name>            (updated YYYY-MM-DD, N documents)

## At a glance
3–5 sentences: education, experience, strongest evidence, languages — as a recruiter would summarise the file.

## Documents
| id | File | Kind | Issuer · date | Pages | Lang | What it proves |
|---|---|---|---|---|---|---|

## Per document
### <title>  (`id`)
- **What it is:** …
- **Key facts:** …
- **Proves:** …
- **Use when:** form asks for … / job mentions …
- **Notes:** quality issues (rotated, low-res scan), sensitive, translation needed …

## Coverage against typical German requirements
| Requirement | Status | Document(s) |
|---|---|---|
| Lebenslauf | ✅ | cv-ai, cv-digital |
| Zeugnis höchster Bildungsabschluss | ✅ / ❌ | … |
| Notenspiegel / Transcript | … | … |
| Arbeitszeugnisse (each employer) | … | … |
| Sprachzertifikate | … | … |
| Anschreiben | written per posting by job-application-writer (stored with the application in `data/applications/`); samples here are style references only |

## Gaps and suggestions
- missing documents, documents worth translating, scans worth replacing with originals.

## Ready-made bundles
| Bundle | Order | Use when |
|---|---|---|
| Zeugnisse komplett | degree → transcript → work references (newest first) → certificates | one "Zeugnisse" upload slot |
| Komplettunterlagen | CV → degree → transcript → references → certificates | form accepts a single PDF only |
```

## C. At application time — choosing files
Look at the form's upload section first: slot names, required marks, number of slots, accepted types, size limit.
Then decide with these rules and put the decision in the ready list for the user:

1. **Typed slots** (Lebenslauf / Zeugnisse / Anschreiben / Sonstiges, or a type dropdown per file) → one file per slot:
   CV alone in the CV slot; certificates in the certificate slot. If a slot is for "Zeugnisse" and the user has several,
   merge them into one PDF unless the form allows several files of that type.
2. **One generic slot or "please combine into one PDF"** (e.g. Oracle Recruiting) → `--merge` in German standard order:
   (Anschreiben) → Lebenslauf → highest degree (Urkunde, then Zeugnis, then Notenspiegel) → earlier degrees →
   Arbeitszeugnisse newest first → language certificates → other certificates → awards. Publications only if asked.
3. **Limited number of files** (e.g. max 3) → CV separate, everything else merged into "Zeugnisse", keep within the limit.
4. **Only a CV is required** → upload only the CV (matching `use_for`). Do not add certificates nobody asked for.
5. **Size limit** → `--max-mb <limit>`; if it still does not fit, drop the least relevant documents and say so.
6. **Language**: prefer documents in the posting's language; mention when only a German original exists for an English posting.
7. **Never** upload `sensitive` documents unless the form explicitly requests that document type, and then ask the user first.
8. **Required document missing** (e.g. Zeugnis höchster Abschluss) → pause and ask the user for it; add it to the knowledge base, then continue.

Produce the files:
```
python3 tools/kb_bundle.py --separate cv-ai --prefix <Last>_<First> --max-mb 10
python3 tools/kb_bundle.py --merge degree-msc,transcript-msc,ref-x --name <Last>_<First>_Zeugnisse --max-mb 10
```
Upload the printed absolute paths with `tools/upload_file.sh`. Record which files went where in the application's Notes.
